# ollama2cpp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Typer + Rich CLI that starts `llama-server` on the GGUF blobs of the user's Ollama models, with a first-run setup flow and a benchmark-driven optimizer that maximizes generation tokens/s.

**Architecture:** Small single-purpose modules under `src/ollama2cpp/` (config, ollama store reader, GGUF header reader, hardware probe, llama.cpp binary/runtime wrappers, selector, optimizer, ui) behind one Typer app. All process/HTTP access goes through two thin seams (`proc.py`, `server.py`) so tests mock them.

**Tech Stack:** Python ≥3.12, typer, rich, psutil; pytest + pytest-cov; ruff; pyrefly.

**Spec:** `docs/superpowers/specs/2026-11-25-ollama2cpp-design.md` (read it first; this plan only fixes names, signatures and tests).

## Global Constraints

- Python `>=3.12`; runtime deps only `typer`, `rich`, `psutil` (JSON config, no TOML writer).
- `ruff.toml` is law: line length 120, Google docstrings (`D`+`DOC`), absolute imports only, `from __future__ import annotations`, no `print` (use Rich), lazy `%` logging, no `shell=True` (subprocess calls carry a `# noqa: S603` with reason, only in `proc.py`).
- Coverage gate `--cov-fail-under=90` on `src/ollama2cpp`.
- Config: `DEFAULT_PATH` = `~/.ollama2cpp`, file `config.json`; defaults host `127.0.0.1`, port `8080`, ctx `8192`.
- Ollama directory is read-only. Never kill a process not recorded in our pid file. Winget id `ggml.llamacpp`.
- Non-stop batch: one bad model/candidate is logged + sentinel, never aborts the command.
- Verify after every task in this order: `uv run ruff format .` → `uv run ruff check . --fix` → `uv run pyrefly check` → `uv run pytest -x`.
- Commit step at the end of each task: only once the user has okayed commits; otherwise stop at the verify step.

## Review Focus

1. Dangling manifest (model layer present, blob file missing) or manifest with no model layer → `list` shows "missing blob"/"unsupported", `serve` errors clearly; nothing crashes. (Task 3, 11)
2. Truncated/corrupt `config.json` → backed up to `config.json.bak`, treated as first run, no traceback. (Task 2)
3. Port held by a foreign process (not our pid file) → clear error naming the port, process never killed. (Task 7, 11)
4. Model names: no tag (`gemma4` → `gemma4:latest`), registry-prefixed, mixed case; paths containing spaces/non-ASCII (Windows user dirs) survive into argv unmodified. (Task 3, 6)
5. CPU-only host (no GPU, `nvidia-smi` missing, `--list-devices` shows only CPU) → selector uses RAM, seed `-ngl 0`, no crash. (Task 5, 8, 9)
